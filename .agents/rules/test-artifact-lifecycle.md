# 测试材料生命周期

- 用户于 2026-11-10 明确要求：Spec 归档后清掉原始证据，本地也不长期保留；本规则优先于通用 Skill 中的证据留存要求。
- 测试必须真实执行并观察结果；报告记录测试版本、命令、时间、结果、缺陷复验和未验证项，不以附件数量证明质量。
- 长期保留计划、报告、账本、测试源码及可复现脚本；日志、截图、trace、录屏、临时 JSON、测试副本和临时 profile 均是可清理运行材料。
- 临时材料默认不入 Git；测试期间按 Spec/run 隔离。成功路径不默认采集截图和 trace；排错材料只保留到问题闭环。
- 运行结束及时删除不再需要的项目/安装包副本及临时 profile，不能把所有轮次的副本一直累积到归档。
- spec-end 顺序：验证并汇总报告 → AWR 机器核验与会话结束 → Spec 原位归档 → 清理本 Spec 的所有临时证据、夹具、副本与缓存 → 检查报告和工作区 → Git 收尾。
- AWR 的 completion-report、evidence-draft、complete-input 等仅服务本轮核验，核验完成后随运行材料清理；账本长期产物引用最终报告。
- 报告须独立可读；清理时移除附件超链接、注明材料已按策略清理，保留历史测试结论及修订记录，不伪造或回填原始证据。
- 清理前核对 Spec 已归档、进程已退出、测试造成的用户数据/快捷方式/ACL 已恢复；校验绝对路径属于本项目，禁止跟随链接删除外部文件。
- 禁止误删用户书库、真实用户 profile、AWR 状态库/配置、开发依赖和交付包；共享缓存仅删除能够确定归属已完成测试的材料。
- 归档后的复验仍按此规则收尾，不因旧 Spec 再次运行而永久积累证据。
