# Windows 安装包与运行路径

当前目标为 Windows 11 x64（Intel / AMD）。本项提供基础窗口的离线安装包，小说编辑、书库操作和最终视觉在后续 Spec 中实现。Windows 10 与 ARM64 不在本次支持范围。

## 构建

在项目根目录，使用 Node 24、npm 11 和锁定的依赖：

```powershell
npm ci
node node_modules/electron/install.js
npm run typecheck
npm run test:unit
npm run dist:win
```

`npm run package` 等价于 `npm run dist:win`。首次构建可能下载 Electron、NSIS 与打包工具；构建机需要网络，生成的安装包不需要联网下载运行时。构建命令不会上传 GitHub 或创建 Release。

| 入口 | 产物 | 用途 |
|---|---|---|
| `npm run pack:win` | `release/win-unpacked/` | 开发检查；必须保留整个目录，不能只复制其中的 exe |
| `npm run dist:win` | `release/Avalon-0.1.0-x64-Setup.exe` | 当前版本的离线安装包；版本名来自 package.json |

## 安装、启动与卸载

双击 Setup.exe，按中文向导选择当前用户可写的独立安装目录。安装只针对当前用户，创建桌面和开始菜单入口；完成页可以启动 Avalon。安装后的应用已包含 Electron 运行时，设计上无需 Node、npm、Git 或项目源码。

安装目录应专用于 Avalon。**不要选择小说书库或其他存放个人文件的目录作为安装目录。** 安装器可能补上应用名子目录，以实际安装路径为准。

安装器会先检查最终目录是否可创建、写入和清理临时文件，再按标准流程自动卸载已有版本并安装新版。预检失败会提示无法写入目录，可点击“上一步”重选；静默安装遇到同样问题返回退出码 2。预检不保证后续权限变化或磁盘空间耗尽时自动回滚。

开发机已有旧版 `Avalon.lnk` 时，安装器可能替换同名入口。验证安装包应优先使用专用测试用户或 VM；如果必须使用当前用户，先备份已有快捷方式并确认其目标，测试结束后恢复，避免破坏依赖源码的旧体验入口。

关闭窗口即退出程序。在 Windows“已安装的应用”中卸载 Avalon，会移除安装程序文件、安装器管理的快捷方式和注册项。正常卸载保留独立 AppData 与安装目录之外的书库。不要向卸载器传 `--delete-app-data`；该参数属于上游卸载器的显式删数据能力，不属于本项目提供的操作流程。

## 文件位置

| 内容 | 位置与职责 |
|---|---|
| exe 与 Electron 运行时 | 所选安装目录；应用运行期间不写入 |
| 应用代码、preload、界面资源 | 安装目录下 `resources/app.asar`，按构建相对路径读取 |
| 安装版用户数据 | Windows 通常为 `%APPDATA%\Avalon`，代码使用 Electron `app.getPath('appData')` 获取平台根路径 |
| 开发态用户数据 | 同一根路径下 `Avalon-dev`；不会混入安装版 |
| Chromium 会话与缓存 | 用户数据目录下 `session` |
| 启动诊断 | 用户数据目录下 `logs/startup.json`，每次启动覆盖一次 |
| 小说书库 | 后续由作者单独选择的普通文件夹，不放安装目录；本项尚未实现业务读写 |

开发态测试可传入绝对路径 `--user-data-dir` 隔离数据；相对路径会被拒绝，安装版忽略此覆盖。安装版测试请使用专用 Windows 用户，不要假定该参数能隔离生产数据。

生产包以本地文件加载界面，不启动 Vite，不占用 5178 端口，也不依赖启动时的工作目录。开发服务仍使用 `127.0.0.1:5178`。

## 启动问题

真正的启动失败会显示中文错误框；目录初始化成功时提示诊断文件位置。若数据目录或日志不可写，提示会说明无法初始化 / 写入日志，控制台启动时还可查看 stderr。诊断包含时间、应用版本、打包状态与错误消息，不记录小说正文。

正常关闭或加载过程中主动关闭窗口不应弹出启动失败提示。目录权限和资源缺失等真实错误仍会退出并返回失败状态。

## 当前分发与验证限制

此包没有可信代码签名，使用临时默认 Electron 图标。开启智能应用控制的电脑可能阻止安装包或安装后的程序；SmartScreen 也可能提示未知发布者。不能承诺其他机器免拦截，也不将关闭系统防护列为安装步骤。将来扩大分发时再接入受信任代码签名并验证相关系统策略。

生成安装包、通过单元测试不等于完成真实安装验收。SPEC-007 的独立测试还需要覆盖中文向导、快捷方式、关闭重开、卸载保留数据，以及本机独立安装目录中的运行验证（内置 Electron 运行时、本地资源、无外部开发工具调用和开发端口）。按用户在 2026-11-10 的决定，不再要求额外干净电脑或虚拟机；本机结果不代表跨机器或断网实测。相关结果以 [测试计划与后续报告](../spec/versions/v0.1/specs/20261109-1640-tech-Windows打包与运行路径/tester/test-plan.html) 为准；本机已关闭智能应用控制，不能作为开启状态的兼容证据。
