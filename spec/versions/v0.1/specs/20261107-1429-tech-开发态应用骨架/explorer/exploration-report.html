3. 外部知识与适用边界

  • electron-vite 官方指南提供 main / preload / renderer 三入口统一构建。采用显式入口和输出格式，避免依赖隐式目录猜测。
  • 更新机制区分 renderer HMR、main 重启与 preload 触发页面重载；使用 dev --watch，不能把任一页面刷新当作全部更新路径已验证。
  • Electron 上下文隔离要求经 contextBridge 暴露窄方法，不暴露 ipcRenderer 或通用通道调用；preload 不是第三个独立进程。
  • Electron 安全建议支持保留 contextIsolation / sandbox、关闭 nodeIntegration，并校验 IPC 来源。开发服务只监听回环地址。
  • 沙箱 preload 限制意味着本例应输出单个 CJS preload 文件；只依赖 Electron 允许的 API，项目常量随文件打入，不通过关闭沙箱解决加载问题。
  • Playwright Electron 支持仍标为实验性。自动化必须启动实际 Electron，另保留人工窗口关闭与开发命令退出检查，不能只用网页代替桌面验收。

4. 对下游的建议

通过一个只读 getAppInfo() 测试端到端通信，不提前搭模块注册框架。应用呈现 Avalon 标题、启动状态和连接检查按钮，最终外观由 SPEC-003 决定。显式生成 main/index.cjs、preload/index.cjs 与 renderer HTML；构建用于校验及 E2E，不代表完成 Windows 打包。

5. 风险与边界

首次依赖下载

npm 包与 Electron 二进制下载都可能受网络影响；实现前记录 registry、锁文件、安装退出码。不得将下载失败改写为应用测试通过。

开发服务与退出

端口冲突、HMR websocket、Electron 子进程退出须独立观测。测试只清理自身启动的进程，不能按进程名关闭其他 Electron 应用。

验收不能越界

本轮无 exe 安装包、小说编辑与读写；窗口尺寸只是技术默认值。未运行安装、编译或 E2E，目前只完成调研。
