3. 设计方案

3.1 工程与依赖

单 package 工程，使用 npm 11 / Node 24；记录 packageManager 与 engines（Node >=24.0.0 <25），仅提交 package-lock.json，后续用 npm ci。候选精确版本：Electron 45.2.3、electron-vite 6.0.0、Vite 8.3.6、React / React DOM 19.3.1、TypeScript 7.0.2、@vitejs/plugin-react 6.2.1、Vitest 5.1.0、@playwright/test 1.65.0。types 包选择匹配主版本并锁入 lockfile。正式版本已从 registry 核验，组合未运行；如安装存在 peer 冲突，先报告具体冲突，不使用 --force 或 --legacy-peer-deps 掩盖。

main、preload 输出分别固定为 out/main/index.cjs、out/preload/index.cjs；renderer 输出 out/renderer/index.html。package.json main 指向 main/index.cjs。preload 合成单个 CJS 文件，只外置 Electron API。构建用于静态校验和桌面测试，不包含分发打包配置。

3.2 启动与权限边界

app.whenReady 后注册 IPC，再创建窗口。初始 1000×700、最小 640×480，仅为技术测试默认值。保留原生标题栏；contextIsolation=true、sandbox=true、nodeIntegration=false。渲染端不导入 Electron 或 Node。阻止新窗口和离开应用文档的导航，拒绝权限请求。

开发模式只接受由 electron-vite 提供的 http://127.0.0.1:5173 文档地址；服务 host=127.0.0.1、port=5173、strictPort=true。端口冲突明确报错，不静默跳端口。build 后 loadFile 加载输出 HTML；地址与 preload 路径由输出文件位置解析，不固定本机绝对路径。开发 CSP 仅为本地脚本 / HMR websocket 开口，构建态禁止远程连接；具体 CSP 文本随类型检查与真实启动验证。

开发地址为 http://127.0.0.1:51735178/，server host=127.0.0.1、port=51735178、strictPort=true；端口冲突明确失败。build 后 loadFile 加载输出 HTML，URL 用 pathToFileURL 生成，与 IPC 可信文档 URL 同源。preload 与资源路径相对输出目录解析。开发 CSP：default-src 'self'; script-src 'self' 'unsafe-inline'; style-src 'self' 'unsafe-inline'; connect-src 'self' ws://127.0.0.1:51735178; object-src 'none'; base-uri 'none'。构建 CSP：default-src 'self'; script-src 'self'; style-src 'self'; connect-src 'none'; object-src 'none'; base-uri 'none'。配置文件按 command 通过 HTML 转换写入对应策略，不扩大其他来源。

Windows / Linux 在 window-all-closed 时 quit；macOS 保留标准 activate 重开逻辑，当前只作结构兼容、不计跨平台验收。加载失败或主进程启动异常记录错误并非零退出，不留下空白窗口假装启动成功。

3.3 数据结构

结构 / 字段类型 / 空值 / 默认值语义
AppInfo.name字面量 'Avalon'；不可空；固定值应用标识
AppInfo.versionstring；不可空；无默认主进程 app.getVersion()，package 初始 0.1.0
AvalonApi.getAppInfo() => Promise<AppInfo>；不可空唯一页面桥接方法
ConnectionState判别联合，默认 {status:'idle'}idle / checking 无附加字段；ready 带 info:AppInfo；error 带 message:string，均非空
IpcCallerwebContentsId:number、frameUrl:string、isMainFrame:boolean；均非空、无默认只用于来源校验，不接受页面自报这些字段

3.4 接口签名与行为

type AppInfo = { name: 'Avalon'; version: string };
interface AvalonApi { getAppInfo(): Promise<AppInfo> }
type ConnectionState =
  | { status: 'idle' | 'checking' }
  | { status: 'ready'; info: AppInfo }
  | { status: 'error'; message: string };
type IpcCaller = { webContentsId: number; frameUrl: string; isMainFrame: boolean };

isTrustedCaller(caller: IpcCaller, expectedId: number, expectedUrl: string): boolean
registerAppIpc(getWindow: () => BrowserWindow | null,
               getDocumentUrl: () => string): () => void
createMainWindow(): Promise<BrowserWindow>
bootstrap(): Promise<void>
getAppInfo(): Promise<AppInfo>  // preload 唯一公开方法
checkConnection(api: AvalonApi | undefined, timeoutMs?: number): Promise<AppInfo>
App(): React.JSX.Element

isTrustedCaller 为纯函数，校验调用者窗口 ID、主 frame 和精确文档 URL；非法 URL 返回 false，不抛异常。registerAppIpc 使用固定通道 avalon:get-app-info，无请求参数；额外参数、子 frame、外部页面或未知窗口分别拒绝，不返回敏感详情；返回取消注册函数。getWindow/getDocumentUrl 来自主进程闭包，启动时未就绪也拒绝。注册一次，主进程重启由新进程重新注册。

createMainWindow 异步等待文档加载，加载失败 reject Error；bootstrap 捕获初始化错误并输出结构化 console 事件后退出码 1。窗口对象在 closed 时清空，activate 时仅在无窗口时重建。

preload 通过 contextBridge.exposeInMainWorld('avalon', api) 暴露对象，不暴露通道名参数、ipcRenderer、event、fs 或 shell。调用拒绝统一变为 Error('IPC_UNAVAILABLE')；成功对象检查 name/version 类型后返回。checkConnection 默认 timeoutMs=3000；API 缺失、请求拒绝、结构错误和超时转为可展示错误，清理 timer，不输出内部栈到页面。页面 pending 时按钮禁用，失败后恢复可点击。

4. 执行模式

实现为 single-agent；工作流为 gated + serial，同一 Agent 分阶段承担角色。测试先行：先建立最小工具配置与失败的行为测试，再补使其通过的实现。没有用户对本方案及测试计划的确认，不创建业务源码。
