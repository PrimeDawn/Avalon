定位到项目继承的 Low 完整性标签；待最小修正实验验证恢复

1. 问题现象与复现

启动前置失败

TC-002 失败并阻塞 9 项真实桌面验收。npm run test:e2e 的 7 个分组均在 electron.launch 失败；electron.exe --version 及最小 BrowserWindow 程序也同样失败，stderr 基本为空。

在仓库根目录运行 node spec/versions/v0.1/specs/20261107-1429-tech-开发态应用骨架/debugger/probes/stdio-probe.mjs。脚本用实际安装的 Electron，记录每个进程的输出、退出码及时间，不依赖 GUI 程序的 PowerShell LASTEXITCODE。前两次原样基线连续失败。未修改全局环境或运行版本。

3. 根因链与证据边界

已确认的直接原因

CreateWindowStationW 被拒绝（5） → CreateAltWindowStation 返回 12 → AlternateDesktop / BrokerServices 传播错误 → Sandbox::Initialize 的 CHECK 失败 → electron.exe+0x348e98a 断点 → 0x80000003。进程只载入系统 DLL 后即失败，没有 Avalon 调用栈，也没有开始验证 React、IPC 或 HMR。

Electron v45.2.3 的 DEPS 固定 Chromium 156.0.8078.80；该版本 sandbox.cc 预创建隔离窗口站并检查结果。window.cc 的两组掩码与本机实时捕获一致；sandbox_types.h 定义错误 12。反汇编中“最近导出符号”仅为位置参考，不能用其 V8 名称判断真正调用栈。

上游 Codex #57505 报告过类似窗口站权限失败，但本机独立探针成功，不能直接套用其 MXC 归因。GPU / 僵尸 SID 问题报告也不等于本机根因。缺少证据确定具体拒绝策略及其来源；尚未证明应用在用户普通终端能成功启动。
