1. 概述

为现有基础窗口提供 Windows 11 x64 离线安装包。用户双击 Setup.exe，经过中文向导选择目录，安装后通过桌面 / 开始菜单启动 Avalon；无需源码、Node、npm、Git 或开发服务器。本项不加入小说编辑、存储业务、最终视觉、自动更新、发布上传或单文件便携版。

首轮为未签名自用安装包。用户已同意不以智能应用控制放行作为完成条件。其他电脑可能拦截；签名与开启该功能的兼容实测留作后续分发工作，不以关闭防护作为产品安装步骤。

3. 设计方案

3.1 构建与安装

精确新增 devDependency electron-builder@26.18.0，同步 package-lock.json，不升级现有技术栈。electron-builder.config.cjs 导出配置对象，无新增配置工厂。appId 固定 io.github.primedawn.avalon，productName / executableName 为 Avalon；asar:true，files:["out/**","package.json"]，输出目录 release，构建资源目录 build；win.target 为 nsis / x64；publish:null，命令仍带 --publish never。

NSIS：oneClick:false、perMachine:false、allowElevation:false、allowToChangeInstallationDirectory:true、installerLanguages:["zh_CN"]、language:"2052"、displayLanguageSelector:false、createDesktopShortcut:true、createStartMenuShortcut:true、shortcutName:"Avalon"、runAfterFinish:true、deleteAppDataOnUninstall:false。include 指向 build/installer.nsh。保留默认原生向导与临时默认图标，品牌图标交由视觉 Spec 统一设计。

include 仅定义无参数宏 customInstallMode（将 $isForceCurrentInstall 设为 "1"、$isForceMachineInstall 设为 "0"）和 customWelcomePage（MUI_PAGE_WELCOME）。不自定义卸载递归删除，不传 --delete-app-data。安装目录选择一个专用 Avalon 子目录，不能选择书库作为安装目录；正常卸载只处理安装产物、注册项与安装器管理的快捷方式。当前支持普通用户可写目录，不以管理员提权规避权限失败。

package.json 脚本完整命令 / 产物
pack:winnpm run build && electron-builder --config electron-builder.config.cjs --win --x64 --dir --publish never；release/win-unpacked，仅开发检查
dist:winnpm run build && electron-builder --config electron-builder.config.cjs --win nsis --x64 --publish never；离线 Setup.exe
packagenpm run dist:win

artifactName 为 Avalon-${version}-${arch}-Setup.${ext}。本项没有签名凭据；不引入假签名，也不禁用 Windows 安全检查。未来可以接 electron-builder 标准签名能力；当前文档须标明未签名。构建机首次可能下载 NSIS / Electron 工具，离线要求针对用户安装和运行。

3.2 路径与数据结构

type RuntimePaths = Readonly<{
  userData: string;
  sessionData: string;
  logs: string;
}>;
type StartupDiagnostic = Readonly<{
  event: 'app-ready' | 'app-start-failed';
  timestamp: string;
  version: string;
  isPackaged: boolean;
  message: string | null;
}>;

以上字段全部必填、无隐式默认值；RuntimePaths 全为绝对路径且不可空。诊断 timestamp 为 UTC ISO 字符串；message 成功时 null，失败时错误消息，不记录稿件内容、环境变量或密钥。每次启动覆盖一个 startup.json，不累计无限日志。

路径规则
preload / renderer保留 __dirname 相对 out/main 的定位；asar 内同样有效。不依赖 process.cwd() 或开发盘符。
生产 userDatajoin(app.getPath('appData'), 'Avalon')
开发 userDatajoin(app.getPath('appData'), 'Avalon-dev')；未打包测试传入 --user-data-dir 时，允许绝对路径覆盖；相对路径拒绝
sessionData / logsuserData/session、userData/logs；ready 前创建并设置 Electron 对应路径
未来书库作者单独选择的普通文件夹，位于安装目录之外；本项只用测试夹具验证卸载不删除，不实现选书或保存业务

3.3 函数契约

文件 / 完整签名行为、返回与错误
runtime-paths.ts
resolveRuntimePaths(appData: string, isPackaged: boolean, userDataOverride?: string): RuntimePaths		纯路径计算；appData 必须绝对路径；未打包且 override 非空时使用绝对 override；打包态忽略 override。相对根或有效覆盖值非绝对时抛 Error('INVALID_USER_DATA_PATH')。省略覆盖默认 undefined。
initializeRuntimePaths(): RuntimePaths调用 Electron getPath 和 commandLine.getSwitchValue；递归创建上述三个目录；调用 setPath('userData')、setPath('sessionData') 和 setAppLogsPath。必须在 whenReady 前调用；文件系统失败保留 NodeJS.ErrnoException 向上传递。
startup-diagnostics.ts
writeStartupDiagnostic(logs: string, diagnostic: StartupDiagnostic): void		UTF-8 JSON 覆盖 logs/startup.json；失败抛 NodeJS.ErrnoException，由调用方处理，不在此吞错。logs 必须是初始化完成的绝对目录。
window.ts
createMainWindow(): Promise<BrowserWindow | null>		保留安全配置与加载方式；加载 rejected 时仅在 window.isDestroyed() 为真时返回 null（用户关闭取消），否则原样抛错。成功 await 后也检查销毁状态。getDocumentUrl(): string 契约不变。
index.ts
openWindow(): Promise<void>		处理 null 返回，不给已销毁窗口注册监听；非 null 时更新 mainWindow 并注册 closed 清理。非取消加载错误继续传播。
failStartup(error: unknown): void保留 stderr；若路径初始化成功则写失败快照，写失败也输出 stderr。通过 dialog.showErrorBox 显示中文启动失败和可用日志位置，再 app.exit(1)。路径初始化失败不捏造日志路径。
bootstrap(): Promise<void>try 内先初始化路径，Windows 上 setAppUserModelId；然后 whenReady → 注册既有 IPC → 创建窗口。窗口存在才写成功快照；日志写入失败只记 stderr，不误判窗口失败。保留现有退出 / activate 规则。最终 catch 进入 failStartup，不产生未处理 Promise。

不新增 IPC 或渲染端文件系统权限；getAppInfo、CSP、contextIsolation、sandbox、nodeIntegration 边界保持原约定。诊断文件不是业务持久化接口。

6. 风险和依赖

  • 未签名可能被智能应用控制或 SmartScreen 拦截，用户已接受本项不验证 SAC 放行；不得声称可信签名或跨机器免拦截。
  • 无开发工具的干净 Windows 11 环境仍是原验收要求；当前未落实。可先完成实现与本机测试，但没有该环境不能把此用例写成通过。用户本次豁免只针对 SAC，不扩展为取消全部干净机验收。D-011：用户取消额外干净 Windows 环境要求。P06 改为本机独立安装及内置运行时、本地资源、无外部开发工具调用和无服务端口的综合验证；不声称跨机器或真实断网测试。
  • 安装 / 卸载可能覆盖同名快捷方式。优先用专用测试账号 / VM；本机验收必须备份已有 Avalon.lnk，核对目标，结束恢复，仅清理测试实例和测试安装目录。
  • 不把测试书库放安装目录；NSIS 会管理整个安装目录。要测试卸载保留的是外部书库与独立 AppData，不承诺保留用户手工塞入安装目录的文件。
  • 路径初始化修改会隔离原开发用户目录；现阶段无业务数据，不做迁移。以后真实数据迁移需独立设计。
  • 代码签名、品牌图标和后续平台支持不因本项默认配置而被宣称完成。
