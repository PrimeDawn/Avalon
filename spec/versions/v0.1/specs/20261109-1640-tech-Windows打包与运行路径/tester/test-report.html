3. 缺陷交接：I-006 / P11

建议级别 major，当前不建议通过测试。复现：正常安装 → 新建专用测试目录并拒绝当前用户写入（不修改系统目录）→ 重开同一安装器，选择该目录的 Avalon 子目录 → 安装。预期在破坏现有安装前识别不可写目录，显示准确错误；实际先移除旧安装，再弹出“Avalon 无法关闭”，此时没有 Avalon 进程。点击取消后安装器退出，原应用及快捷方式已移除，外部书库和 AppData 标记哈希未变。

现象证据来自本轮原生向导。只读线索：electron-builder 的 node_modules/app-builder-lib/templates/nsis/include/extractAppPackage.nsh:116 在复制失败时使用通用 appCannotBeClosed 文案；build/installer.nsh 当前只有安装模式及欢迎页宏。尚未进入 debugger 修复，也没有改产品实现。交接建议：检查目录可写性预检与重装顺序，再用同一失败路径复验。

补充缺陷交接：I-007 / P09

用例位置 tests/packaged/packaged-shell.spec.ts:79；执行命令 npm run test:e2e -- --config playwright.packaged.config.ts --grep P09。同一未修改产品包在早关闭测试中显示启动失败，实际快照（已清理）记录 ERR_FAILED，测试进程退出 1（已清理）。测试超时后 worker 回收，错误框随进程消失；并非成功退出 0。

建议级别 major；先定位再修复。测试未在 close 调用前持久化阶段标记，故现有证据不能单独断言失败精确发生在 close 调用之前或之后。只读线索为 src/main/window.ts:43–48 的加载取消与销毁判断；不把初步时序推测写成已证实根因。下一轮需加入阶段审计，再在相同包 / 同一路径复验。

本轮最后一次预检仍为类型检查、70 项单元和 build 通过；P09 真实失败保留原日志。最终机器恢复证据（已清理）记录 64 / 92 个 profile 文件及旧快捷入口校验。
