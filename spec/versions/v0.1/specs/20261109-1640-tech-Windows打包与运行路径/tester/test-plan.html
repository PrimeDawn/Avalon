1. 验收口径与环境

测试对象为同一工作树生成、记录 SHA256 的 Windows 11 x64 未签名离线 Setup.exe；build 工程通过不能替代安装验收。模式 gated / serial。当前只写计划，所有用例均未执行。

环境用途 / 限制
开发机 Windows 11 x64，Node24 / npm11类型、单元、包检查和自动化；SAC 已由用户关闭，不能证明开启时兼容
普通 Windows 用户 / 专用测试用户原生向导、真实桌面与开始菜单、卸载；保护已有快捷入口
干净 Windows 11 x64 VM 或实体机本机 Windows 11 x64 的独立安装目录无源码 / Node / npm / Git；运行前记录已装软件、命令可用性与系统版本。此环境尚未提供，不以伪装 PATH 替代检查内置运行时、资源白名单、真实安装入口、本地 file URL、IPC 和无应用监听端口；机器本身保留开发工具，不伪装跨机器验证

离线仅在专用测试 VM / 机器上断开网络或使用该环境的网络隔离；不擅自断开用户主机网络。本轮不要求断网实测；通过完整离线安装包、本地资源和无外部网络依赖检查验证独立运行，不断开用户主机网络。SAC 开启态与签名验证根据 D-007 退出本项完成条件，报告明确标记未覆盖。

3. 自动化入口与数据

测试阶段由 tester 修改 scripts/run-e2e.mjs，仅增加当前 Spec 路由；新增独立 packaged config 与 tests/packaged/packaged-shell.spec.ts。自动化使用完整打包 exe，验证 app.isPackaged 为 true、页面内容、原有 getAppInfo、file URL、进程退出、控制台与请求记录。保留 Electron sandbox，不使用 --no-sandbox。

$env:AVALON_TEST_SPEC_DIR = 'spec/versions/v0.1/specs/20261109-1640-tech-Windows打包与运行路径'
npm run test:e2e
$env:AVALON_PACKAGED_EXE = (Resolve-Path 'release/win-unpacked/Avalon.exe').Path
npm run test:e2e -- --config playwright.packaged.config.ts
Get-FileHash 'release/Avalon-0.1.0-x64-Setup.exe' -Algorithm SHA256
Get-AuthenticodeSignature 'release/Avalon-0.1.0-x64-Setup.exe'

上面命令在测试脚本实现后执行；本轮不执行。生产 app 忽略 --user-data-dir 覆盖，新打包测试应使用专用用户，或在无现有正式 userdata 时创建并清理仅本次测试目录；若已有数据先保护，不覆盖。路径单元测试使用临时目录和文件夹具，不更改真实 AppData。

测试小说仅为外部目录中的三个 UTF-8 文本夹具，固定中文 / 标点 / 换行内容，测试前后由脚本计算 SHA256；不是已实现小说存储功能。权限错误优先用“目标应为目录却是文件”注入，不重复改用户权限。

4. 日志审计与证据

每次运行独立保存到 tester/artifacts/test-logs/<run-id>。自动化记录命令、开始结束时间、退出码、OS/build、版本、Git SHA、工作区状态、锁文件和安装包 SHA256。Playwright 保留截图、trace、console/pageerror、请求失败及 stdout/stderr；网络为空也由实际观测记录。原生安装过程由实际屏幕捕获与步骤记录证明，另导出快捷方式目标、卸载项、PID 树、安装目录清单和夹具哈希。

失败时关联同一 run-id 的 CodeIntegrity / Application 事件；若安全策略拦截，记录原始原因，不改策略后偷偷算通过。原始机器证据由命令和捕获工具生成，不手写通过 JSON。个人路径在对外文档中脱敏，日志不收集正文或凭据。

5. 测试节奏与失败处理

先跑单元 / 构建 / 静态包检查，再集中进行一轮窗口会话和必要的关闭重开；无新改动、无失败时不重复启动。普通功能共用会话；极早关闭、失败副本、快捷入口分别启动。用例开始前说明目的，完成后仅结束本次 PID。当前无需打开任何应用。

全部必需用例真实通过才建议确认测试；P06 缺环境时保持 blocked。全部修订后必需用例真实通过才建议确认测试；P06 以本机综合证据判断，缺少第二台机器不再标 blocked。缺陷交 spec-debugger，本阶段不直接修产品；修复循环预算在首次需要修复前依账本确认。SAC 开启态不再是必需用例，但报告必须保留覆盖限制。
