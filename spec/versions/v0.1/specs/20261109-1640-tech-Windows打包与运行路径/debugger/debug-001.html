现象与假设

awr status 经 Node 启动器报 spawn UNKNOWN；直接原生 awr.exe 提示应用程序控制策略阻止。假设：智能应用控制拒绝当前未签名二进制，而非 PATH、项目完整性标签或 Node 包损坏。

复现和证据

观察实际结果
Get-AuthenticodeSignature，已安装 0.6.0NotSigned；SHA256 BCEBFBBD8D2948317A8A5B9CC1BF76218BE78E60EB79AD5CDD5BFC13F8E0ED78
文件流只有 :$DATA，无 Zone.Identifier；不是下载标记待解除
CodeIntegrity 3077 / 3033明确记录阻止 awr.exe；策略 0283ac0f-fff1-49ae-ada1-8a933130cad6
CodeIntegrity 3099 与策略值同 ID 名称 VerifiedAndReputableDesktop；VerifiedAndReputablePolicyState = 1
官方 npm 0.7.0 独立检查NotSigned；SHA256 42125F7D617A109A73F087CB9E05F6C61DA8D02428A252DBB0B7FCF5EAAA5151；直接 --version 同样被阻止，退出 1。未替换已安装版本

根因与处理结果

日志、签名和同一策略 ID 相互印证。用户自行关闭智能应用控制后，原安装 0.6.0 的 awr --version、awr status 立即正常（退出 0）；随后 session start --claim、work progress、work prepare 均成功。只改变策略状态便解除拦截，根因得到验证。Agent 未修改 Windows 策略、PATH、项目权限或 AWR 安装。

这是用户主动更改本机系统设置后的恢复，不是应用签名问题已修复。用户反馈此设置在当前机器无法重新开启，尊重实际状态，不尝试注册表修改或重置系统。微软 SAC 说明。

方案关联与后续

无产品代码修复；不产生虚构 debug-fix 或产品测试通过记录。I-001 可关闭。打包产品另按 D-007：未签名自用包可先做，开启 SAC 的兼容与签名未验证，不能用本机运行结果外推。
