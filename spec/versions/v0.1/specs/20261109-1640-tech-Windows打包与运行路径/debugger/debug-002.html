1. 范围与用户口径

用户已明确要求修复缺陷，并接受“检测旧安装 → 检查目标目录可写 → 调用旧版卸载 → 安装新版”。本诊断保持标准自动卸载流程、当前用户安装、数据保留和现有窗口功能。安装预检失败应准确告知目录不可写并允许返回修改，不以提权或修改目标权限解决。

2. 历史经验与基线

exp-search 命中 EXP-003：已有加载期间关闭的 ERR_FAILED 观察及 Codex / Explorer 路径差异；KNOW-002 给出三进程和隔离边界。本轮使用正式包的隔离副本和独立 AppData；不改桌面入口，不写用户 profile，不使用电脑操作模式。正式 app.asar SHA256 为 9a04156f6ec961a56bd408c927a49fd54cbbc0309e10678426046f7a8b10fb43，实验后未变。

3. P09：单一假设与可证伪实验

假设：关闭事件已经发生，但 loadFile 取消拒绝先于窗口销毁；只检查 isDestroyed 会把正常关闭当成启动失败。若假设不成立，应当看不到“close-event → load-rejected 且 destroyed=false → error-box”这一顺序。

命令：node spec/versions/v0.1/specs/20261109-1640-tech-Windows打包与运行路径/debugger/probes/trace-close.cjs，探针命令退出 0（表示实验采集成功，不表示产品通过）。源探针 trace-close.cjs；完整实际事件和退出码。

条件实际顺序 / 结果
对照：did-finish-load 后关闭加载完成 → close → closed → window-all-closed → will-quit；产品退出 0，无错误框调用。
复现 1：did-start-loading 后关闭close-event 时 destroyed=false → load-rejected(ERR_FAILED) 时 destroyed=false → isDestroyed=false → error-box → closed-event；产品退出 1。
复现 2：相同事件条件同样顺序与 ERR_FAILED；产品退出 1。两次均未超时。
已验证根因：src/main/window.ts:43–48 将“窗口已销毁”当作“用户已请求关闭”的唯一依据。实际关闭是异步过程，取消页面加载时尚未销毁，错误被抛到 src/main/index.ts:12–32 的 failStartup，显示错误并退出 1。单元 mock 直接把 destroyed 设为 true，遗漏了该中间状态。

实验边界：只在私有副本增加事件记录、show:false、独立 appData 和错误框调用记录；原加载逻辑未改。错误框被记录函数代替以避免阻塞，产品真实错误框已有上一轮截图。两个时序组使用相同插桩，唯一控制变量为关闭触发事件。后续仍需原生正常窗口复验。

4. P11：单一假设与可证伪实验

假设：安装器复制文件失败时无差别选用 appCannotBeClosed 文案，不是确实检测到 Avalon 无法关闭。如果没有应用进程时，写入被拒绝仍进入该分支，即可验证。

命令：node spec/versions/v0.1/specs/20261109-1640-tech-Windows打包与运行路径/debugger/probes/trace-installer.cjs，探针命令退出 0；探针源文件、NSIS 编译日志、运行结果。直接执行安装依赖中的 extractUsing7za 宏，仅将错误框改为输出其消息键并退出，不替换复制、重试或分支判断。

条件实际结果
可写临时目录payload 写入成功；探针退出 0；Avalon 进程数 0。
不可写临时目录 1第五次复制失败进入 appCannotBeClosed；payload 不存在；进程数 0；探针退出 7。
不可写临时目录 2相同错误分支、第五次失败、进程数 0；探针退出 7。

退出 7 是本诊断探针设置的分支标志，不能冒充正式安装器退出码。测试新增的显式写入拒绝规则已恢复；清理计数曾将既有继承拒绝规则也计入，后按规则来源核对，未改继承规则（最终清理证据）。没有修改系统目录或用户安装目录的 ACL。首次探针准备发现 7zip-bin 模块不存在，改用本机 electron-builder 已缓存的 7za，不安装或升级依赖。

已验证根因：node_modules/app-builder-lib/templates/nsis/include/extractAppPackage.nsh:107–116 在 CopyFiles 失败五次后使用 appCannotBeClosed。项目 build/installer.nsh:1–9 未加可写性预检，因此权限错误到复制阶段才暴露。node_modules/app-builder-lib/templates/nsis/installSection.nsh:52–67 明确先调用 uninstallOldVersion、再安装文件，这就是当前自动替换旧版的正常机制，不另造卸载流程。

5. 最小修复方案

范围拟修改验证要求
P09在创建窗口时追踪关闭请求，加载取消时结合关闭状态识别正常退出；继续传播无关闭请求的真实加载错误。只改 window.ts 及对应聚焦测试，不改 IPC 或数据模型。将“close 已发生但 destroyed=false”的状态加入失败先行测试；复用本轮事件探针与 P09；正常加载/关闭及缺失 renderer 仍分别退出 0/1。
P11在用户选择的最终目录确定后、标准安装章节开始前加入可写性检查：验证目录可创建并用唯一临时文件实际写入后清理；失败给出明确中文目录提示并允许返回修改。保留内建旧版卸载与数据保留机制，不提供回滚或多版本功能。可写、中文空格、已存在目录、不可写目录均测试；不可写时标准卸载阶段尚未开始。验证同目录重装仍自动卸载旧版、安装新版，数据不丢。

NSIS 接入优先使用项目 include 的自定义页面/回调扩展点，保留 electron-builder 的目录归一化。不会直接修改 node_modules 或维护整份安装器脚本；静默安装若涉及同一预检入口须明确验证，不能因 GUI 通过就宣称覆盖。写入权限在预检后仍可能变化，预检不承诺原子安装或回滚。

与已确认方案的关系：P09 修正 R4 明确要求的关闭取消处理；P11 根据用户最新明确口径补目录前置检查和准确提示，R2/R5 自动安装、卸载与数据保留保持不变。writer/plan.html 不修改，取舍记录在本诊断和 D-012。
