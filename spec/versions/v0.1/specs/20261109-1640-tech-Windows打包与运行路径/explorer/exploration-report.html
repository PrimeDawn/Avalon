1. 历史经验

检索关键词：Electron、安装、exe、中文路径、完整性标签、桌面入口。命中 EXP-002、EXP-003、KNOW-002。此前 Low 完整性标签导致 Electron 启动失败；桌面启动器曾受进程退出码与 Codex MSIX 路径视图影响。因此验收必须包含真实资源管理器和快捷方式启动，不能只依赖 Agent 子进程。

  • EXP-002：完整性标签
  • EXP-003：桌面入口与退出码
  • KNOW-002：开发态骨架

2. 项目现状

从 dev 的 e02680d 创建本分支；SPEC-001 已完成。现有 Electron 45.2.3、electron-vite 6.0.0；Node 24 / npm 11 是开发工具。build 仅生成 out/main、out/preload、out/renderer，没有分发包配置。正式包应内置 Electron 运行时，用户不安装 Node。现有桌面入口依赖本地仓库，不是分发产物。

src/main/window.ts 已按构建目录定位 preload 和 renderer；生产态忽略开发 URL，以 loadFile 加载。开发端口为 5178，正式包不启动 HTTP 服务。主进程尚无显式数据目录与启动诊断约定。极早关闭窗口可能把已销毁窗口的加载取消误报为启动失败，需限定修正。

现有 52 项单元、8 组桌面测试是历史基线，本轮尚未执行产品测试。scripts/run-e2e.mjs 证据路径固定为 SPEC-001，需要可选的当前 Spec 路由，避免本项证据写入已归档目录。

3. 外部知识与选择

方案判断
electron-builder 26.18.0 + NSIS保留现有 electron-vite 工程；生成离线中文安装向导，作为本项方案。
electron-forge / Squirrel需要额外构建流程适配；当前没有迁移收益。
portable / zip / nsis-web前两种不作为本项正式交付；Web 安装器需额外下载，不符合离线安装方向。

使用 v26 文档，避免误用网站默认的 v27 配置。NSIS 支持 assisted 模式、目录选择和中文语言；perMachine:false 本身不强制只安装当前用户，需 customInstallMode。采用小型 include，而非维护完整安装器脚本。electron-builder v26 NSIS

只读解包 app-builder-lib@26.18.0 检查了 assistedInstaller.nsh、uninstaller.nsh：普通卸载默认不删除 AppData；显式 --delete-app-data 会触发删除。本项不传该参数、不提供删除用户数据操作；书库要求位于安装目录之外。deleteAppDataOnUninstall 的文档适用限制不能替代卸载实测。

asar 默认支持内嵌应用代码；文件白名单仍会包含 package.json 与生产依赖，应检查实际包内容。包内容文档。Electron 的 appData / userData / sessionData 是平台路径 API；sessionData 需在 ready 前设置。Electron app API

智能应用控制依赖信誉或可信签名；代码签名是正式分发的后续接入点，不能承诺所有安全策略都会放行。微软代码签名说明。用户明确没有证书和开启该功能的测试机，同意本次先交付未签名自用包；不配置自签证书、不修改系统信任、不购买服务。

4. 下游建议与风险

  • 目标 Windows 11 x64（Intel / AMD）；不承诺 Windows 10、ARM64。未适配的平台不是本次测试通过范围。
  • 安装文件、应用数据、未来小说书库分离；所有路径来自系统 API / 构建相对位置，不依赖 cwd。
  • 真实安装、快捷方式启动、关闭重开、卸载保留数据是验收主线；包目录测试只能提供部分证据。
  • 本机未发现 Windows Sandbox / 现成 VM 命令。无 Node / npm / Git 的干净 Windows 环境尚未落实，不能把临时改 PATH 当作干净机器。
  • AWR 故障已由用户关闭智能应用控制后解除；原 0.6.0 运行正常，无需升级。详细证据见诊断报告。
  • 反思：现有记忆已覆盖路径视图与退出码；新打包选择尚未实现验证，先保存在本报告，收尾时再沉淀验证后的架构记忆。
