### 范围与验收标准

1. Windows 交付包可在未安装 Node.js / 开发工具的目标机器上启动；允许 exe 携带依赖目录，暂不要求单文件便携 exe。安装包形态、目标 Windows 版本及架构在 SPEC-007 确认。打包 Spec 先验收基础窗口；版本验收再验证装有全部功能的最终包。
2. 新建一本书、至少三章，输入中文、标点与多段正文；保存、切章、退出重启后标题和正文一致，能够继续修改。
3. 正文以内容视图编辑，不要求用户操作 Markdown 标记。首版支持标题和正文段落；复杂排版不纳入。支持内容的 Markdown 往返不丢失，遇到不支持内容时明确提示并避免静默覆盖。
4. 保存按钮与 Ctrl+S 可用，显示已修改 / 已保存 / 保存失败。切章、切书、关闭窗口时，未保存内容提供保存 / 放弃 / 取消；保存失败保留编辑内容，不能显示为成功或继续关闭丢稿。
5. 稿件为本地普通 Markdown，能用其他文本编辑器查看；账号、联网及 AI 配置不是写作前提。
6. 核验中文输入法组合输入、撤销重做、粘贴，以及中文和带空格路径、保存失败。性能以单章编辑为单位，SPEC-006 在实现前确定测试样本与可测阈值，本轮不承诺未经验证的数值。

**本版暂缓：** 整本 TXT / Markdown 导入与自动切章（SPEC-005）；右侧多工具标签功能；删除、拖拽排序、自动保存、字数统计与专注模式。SPEC-003 改为本版窗口视觉与必要外壳，不再合并进书库操作。书名重命名是否需要另在书管理 Spec 对齐；章节标题修改纳入本版。不为后续 AI、wiki 等建立通用注册体系作为首版验收要求，保留必要模块边界即可。

**后续版本：** AI、embedding、wiki、大纲工具、地图、生图、同步。遵守 DESIGN.md §11 的现有边界。

**依赖与交付：** 技术路径 SPEC-001 → SPEC-007 → SPEC-002；界面路径 SPEC-001 → SPEC-003；两条路径汇合到 SPEC-004 → SPEC-006 → 最终 Windows 包整体验收。设计探索可在骨架前进行，视觉稿确认后再实现外壳；优先早验 exe，避免末尾才发现打包问题。交付可运行包、使用说明和测试记录；冻结 / 发布日期待估算后确认，不自动沿用旧日期。

## 历史基线（r1，已由当前正式范围替代）
## 1. 版本目标

交付 Avalon 的**地基版**：应用窗口、文件系统（书库 / 章节 / 整本导入）、所见即所得编辑器三块可运行的地基。

本版本不交付任何 AI 能力，但必须一次性把**模块边界、路径处理、IPC 契约**打正，使后续 wiki、技能访谈、AI 改写、检索记忆、地图、生图都只需"加模块"，不改地基。

**地基硬约束**（验收时逐条核）：
- 不写死任何路径：书库根、用户数据目录、临时目录、资源目录一律运行时解析，Windows 优先但架构上可编译 macOS / Linux
- 不写死任何业务枚举：章节状态、wiki 类型、技能种类均为可扩展注册表，不在 UI 里硬编码
- 模块以契约注册：后续能力通过模块注册表挂载，新增模块不修改既有模块代码
