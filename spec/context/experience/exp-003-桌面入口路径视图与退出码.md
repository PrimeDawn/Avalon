# 桌面入口路径视图与退出码

## 困境

桌面快捷方式曾出现两类独立故障：正常关窗后 ExitCode=null 被当作失败；Agent 启动成功而 Explorer 双击无响应。第一次交付只验证出现窗口，漏验了真实入口、关闭与重开。

## 策略

1. Windows PowerShell 5.1 的 Start-Process + 重定向 + PassThru 对照中，立即保存 Process.Handle，再等待退出，能够正确读取 0 / 7 退出码。错误对话框显示前释放 mutex，避免挡住下一次启动。
2. 若双击后启动日志没有更新，先排查脚本是否真的进入。通过 Explorer 启动的进程检查目标路径存在性，不以 Agent 自己的 Test-Path 代替用户视图。
3. 本机 Codex MSIX 内写入普通 LocalAppData 路径实际进入包 LocalCache。Explorer 采集结果 ordinaryAppDataScriptExists=false、codexRedirectedScriptExists=true，证明路径视图差异。
4. 本机辅助入口移至 C:\Users\35692\.avalon-desktop，GUI wrapper 隐藏启动 PowerShell；桌面 Avalon.lnk 指向该入口。每次先 build，成功才打开本地 Electron 页面，失败保留日志。
5. 从 Explorer 真正双击，观察连接成功，点右上角关闭，确认 exitCode=0 与辅助进程退出，再双击重开。用户随后确认正常。

## 理由与边界

启动器验收必须沿实际用户入口完成整条生命周期。Agent 子进程继承的路径视图和环境不能代表 Explorer。这里只是本机体验工具，依赖当前仓库、Node 和 node_modules，不能算 SPEC-007 的可分发 exe。现阶段页面尚未加载时立即关闭曾触发 ERR_FAILED(-2) / exit1；这与空退出码误报不同，已作为打包启动生命周期观察项保留。
